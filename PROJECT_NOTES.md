# FinBG — рабочие заметки

## Цель проекта

Система финансового контроля малого бизнеса по поставкам запчастей и оборудования.
Основная задача первого этапа — заменить ручной учёт в Excel и связать реальные поступления денег с документами продаж (счётами и спецификациями).

## Архитектура

- Backend: Python / FastAPI (`api/`)
- Frontend: React / Vinext (`web/`)
- База данных: PostgreSQL на VPS
- Репозиторий: `git@github.com:nip1976-web/FInBG.git`
- Локальный интерфейс: `http://localhost:5173`
- Локальный API через SSH-туннель: `http://localhost:8000`

## Модель данных и логика

- `payments` — фактические движения денег из PaymentsBattery.
- `deals` — документы продаж из Buyers: счёт или спецификация.
- `payment_allocations` — связи «платёж → сделка» с суммой распределения.
- Один документ может быть оплачен несколькими платежами.
- Один платёж можно распределить между несколькими документами.
- Исходные Excel-файлы не перезаписываются: все связи и ручные решения хранятся в PostgreSQL.

## Импортированные данные

- Входящие Payments: данные с 01.01.2026 из `РС-Поступ-Хольц` и `ПоступленияН`.
- Сделки Buyers: строки из `СчетаРуб`, относящиеся к 2026 году по дате оплаты.
- Загружены контрагенты и менеджеры, необходимые для сделок.

## Интерфейс «Загруженные данные»

- Вкладка `Входящие Payments` — фактические поступления.
- Вкладка `Сделки Buyers` — сделки с колонками:
  - покупатель;
  - вид документа;
  - номер документа;
  - дата документа;
  - сумма сделки;
  - оплачено клиентом;
  - остаток в RUB;
  - остаток в EUR.
- При выборе сделки нижняя часть экрана показывает связанные оплаты и нераспределённые операции выбранного покупателя.
- Можно вручную распределить операцию на сделку с указанием суммы.
- Остаток в EUR рассчитывается по актуальному официальному курсу EUR ЦБ РФ.

## Соответствия названий клиентов

Таблица `payment_client_aliases` содержит соответствия между названием плательщика в Payments и покупателем в Buyers.

Подтверждены:

- `ЛДК 2 ООО` → `ЛДК2, Вытегра`
- `Физ лицо - клиент` → `ФизЛицо`

По подтверждённым соответствиям созданы однозначные связи платежей со сделками. Новые соответствия сначала формируются как предложения для проверки, а не применяются автоматически.

## Внешние интеграции

### Альфа-Банк

Возможна загрузка операций по расчётному счёту через API выписок для юридических лиц. Нужны зарегистрированное приложение/вебхук, права на счёт и секреты доступа, сохранённые только на VPS.

### Bitrix24

Возможна интеграция через REST API: сделки, компании, контакты, менеджеры, пользовательские поля, товары, оплаты, задачи, проекты/группы и смарт-процессы — в пределах выданных прав. Следующий шаг: тестовое чтение сделок, ответственных, компаний и пользовательских полей.
